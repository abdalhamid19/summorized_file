# إعادة قياس الصلاحية وشجرة الواجهة

**التاريخ:** 15 أكتوبر 2026

**الهدف:** قياس مستوى العمليات التي حدّدها المستخدم، ثم فحص ما إذا كانت شجرة واجهة FastVPN تعرض عناصر داخلية. لم يتضمن الاختبار الاتصال بالـVPN أو تغيير موقعه.

## النتيجة المختصرة

- بقي `FastVPN.exe` PID `6052` عند مستوى **High**، وبقيت عمليات التحكم المحددة عند مستوى **Medium**.
- بعد إظهار نافذة FastVPN وقراءة حالتها من جديد، احتوت شجرة **Accessibility** (إمكانية الوصول؛ تمثيل آلي لعناصر الواجهة) على نافذة الجذر فقط. لم تظهر أزرار أو عناصر داخلية.
- لم تُرفع صلاحية `node_repl.exe` الجاري، لذلك **لم يُجر اختبار الشجرة بعد رفع أداة التحكم إلى High**. الاختبار المنفذ هو قراءة النافذة من أداة التحكم ذات مستوى Medium.
- لم أغيّر حالة اتصال FastVPN أو موقعه.

## قياس رموز الوصول

قُرئ **Integrity Level** (مستوى سلامة العملية في Windows) و**TokenElevation** (هل رمز الوصول مرفوع) مباشرة عبر `OpenProcessToken` و`GetTokenInformation`، للقراءة فقط.

| العملية                                     |            PID | مستوى السلامة          | الرمز مرفوع؟ |
| ------------------------------------------- | -------------: | ---------------------- | ------------ |
| `FastVPN.exe`، مالك نافذة FastVPN           |         `6052` | High — `S-1-16-12288`  | نعم          |
| `node_repl.exe` الذي حدده المستخدم          |         `3348` | Medium — `S-1-16-8192` | لا           |
| `node.exe` المرتبطان اللذان حددهما المستخدم | `2652`, `7880` | Medium — `S-1-16-8192` | لا           |
| `ChatGPT.exe`، مالك نافذة ChatGPT           |        `17996` | Medium — `S-1-16-8192` | لا           |
| `codex.exe` الوارد في القياس السابق         |        `10072` | Medium — `S-1-16-8192` | لا           |
| عملية `codex.exe` أخرى ظهرت في القياس       |        `26392` | Medium — `S-1-16-8192` | لا           |

ظهرت أيضًا عمليات أخرى باسم `node_repl.exe` في الجهاز وقت القياس، وكانت Medium. لذلك يثبت قياس PID `3348` حالته كما طلب المستخدم، لكنه لا يربط كل عملية `node_repl.exe` أخرى بجلسة Codex الحالية؛ الاسم وحده لا يكفي لتحديد مالك كل جلسة. رُبطت نافذتا FastVPN وChatGPT بمالكيهما باستخدام `GetWindowThreadProcessId`، ثم قيس رمز كل PID. قد توجد عمليات مساعدة أخرى بالاسم نفسه ومستوى مختلف، لذا يقتصر سطر ChatGPT هنا على العملية التي تملك نافذته.

## فحص شجرة FastVPN

1. أعادت `sky.list_apps()` تطبيق FastVPN ونافذته، بمعرّف نافذة مؤقت `197428`.
2. ظهرت النافذة أولًا بحالة مصغّرة. نُشّطت النافذة فقط، ثم أُعيد جلب مرجعها وقراءة حالتها. لم يُضغط أي زر داخل التطبيق.
3. أُخذت القراءة باستخدام `sky.get_window_state` مع `include_text: true` و`include_screenshot: false`.

النص الذي أعادته الشجرة:

```text
Window: "FastVPN", App: FastVPN.exe.
    0 window FastVPN Secondary Actions: Raise

The focused UI element is 0 window FastVPN Secondary Actions: Raise.
```

`Raise` هنا إجراء لإظهار النافذة، وليس عنصر تحكم داخل FastVPN. لم تتضمن الشجرة أزرار **Connect VPN** أو **Locations** أو **Settings**.

## هل يثبت ذلك أن UIPI هو السبب؟

تعمل العمليات التي حددها المستخدم، وكذلك عمليات `node_repl.exe` التي رُصدت، بمستوى Medium بينما FastVPN بمستوى High. يتوافق غياب العناصر مع **UIPI — User Interface Privilege Isolation** (عزل واجهة المستخدم بحسب مستوى الصلاحية)، إذ توضح Microsoft أن UIPI يقيّد التفاعل من مستوى سلامة أقل إلى أعلى. يمكن لعميل فحص يعمل فعلًا بمستوى High أن يختبر التفاعل عند مستوى مماثل للتطبيق؛ ويمكن لتقنيات المساعدة المؤهلة استخدام **UIAccess** ضمن شروط خاصة. راجع [قيود UIPI وUI Automation لدى Microsoft](https://learn.microsoft.com/en-us/windows/security/threat-protection/security-policy-settings/user-account-control-allow-uiaccess-applications-to-prompt-for-elevation-without-using-the-secure-desktop) و[نظرة Microsoft على أمان UI Automation](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview).

لكن القراءة الحالية لا تحسم ما إذا كان رفع أداة الفحص سيُظهر العناصر؛ لم يُجر اختبار High مقابل High. وقد تكون هناك عوامل إضافية، مثل دعم FastVPN لمزوّد **Accessibility** (المكوّن الذي يعرّف عناصر النافذة للأدوات) أو طريقة رسم واجهته.

## لماذا لم تُرفع العملية الحالية؟

القياس أثبت أن PID `3348` ما زال Medium. لا تتيح جلسة التحكم الحالية طريقة مدعومة لتغيير رمز وصول العملية الحية إلى High من داخلها. آليات Windows الموثقة لبدء عملية برمز أمني محدد، مثل `CreateProcessAsUser`، **تنشئ عملية جديدة**؛ ولا تغيّر رمز العملية القائمة. وتوضح Microsoft كذلك أن تطبيقًا يحتاج رمز المسؤول يمرّ بموافقة UAC (التحكم بحساب المستخدم). راجع [CreateProcessAsUser](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessasusera) و[طريقة عمل UAC](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/how-it-works).

تشغيل نسخة جديدة مرتفعة من `node_repl.exe` لا ينقل اتصال `mcp__node_repl` الحالي أو جلسة `@oai/sky` إليها تلقائيًا؛ لذلك لن يثبت هذا الإجراء أن أداة التحكم النشطة نفسها أصبحت High. وتشغيل Codex بالكامل كمسؤول يوسّع الامتياز إلى التطبيق ومكوّناته الأخرى، ولا يوفر اختبارًا محدودًا لعملية التحكم المطلوبة.

تحديث ACL: أفاد المستخدم أن دعم Namecheap أكد أن `Everyone: Allow FullControl` إعداد متوقع وصحيح ولا يمثل مخالفة. لم نراجع رد الدعم مباشرة؛ ومع ذلك نسحب التحذير السابق من اعتبار هذه القاعدة مانعًا لاختبار قارئ UIA مرتفع، ولا نوصي بتعديلها يدويًا اعتمادًا على التقرير السابق. راجع [[توضيح أذونات تثبيت FastVPN]].

## خطوات ممكنة للوصول إلى اختبار حاسم

1. اختيار أداة فحص UIA مناسبة من [[أدوات فحص شجرة FastVPN بمستوى High]]؛ لا يلزم إصلاح ACL قبل هذا الاختبار وفق إفادة المستخدم عن رد Namecheap.
2. سؤال Namecheap عن CLI أو API رسمي للتحكم بالتطبيق؛ فهذا يتجنب الاعتماد على النقرات إن كانت هناك واجهة مدعومة.
3. إذا لم توجد واجهة رسمية، شغّل فاحص UI Automation ضيق المهمة بمستوى High عبر موافقة UAC، بدل رفع مستضيف JavaScript عام. سجّل PID الفاحص وIntegrity Level وTokenElevation وTokenUIAccess كلًّا على حدة قبل قراءة الشجرة. ويمكن تقييم **UIAccess** فقط إذا كانت الأداة تقنية مساعدة مؤهلة؛ فهو امتياز مختلف عن High وله شروط توقيع وتثبيت آمن. توضح Microsoft [متطلبات UIAccess وحدوده](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview).
4. قراءة الشجرة من عميل الفحص المرتفع في الجلسة التفاعلية نفسها، وتسجيل هويته ومستوى سلامته. عندها فقط يمكن مقارنة شجرة Medium السابقة بشجرة High وتحديد ما إذا كان اختلاف المستوى غيّر النتيجة.

حتى ذلك الحين، النتيجة الدقيقة هي: **شجرة FastVPN قرأها عميل Medium وأظهرت نافذة الجذر فقط؛ ظهور العناصر عند High لم يُختبر.**
