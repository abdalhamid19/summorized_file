## 🟢 Phase 0: قبل البدء

- [ ] 0.1 شغّل [[Claude Code]] على مهمة طويلة (إصلاح اختبارات مثلًا) في المجلد الرئيسي
- [ ] 0.2 ثبّت [[Warp]] إن أردت الأتمتة (المتحدث يترك رابطه في وصف الفيديو)
- [ ] 0.3 حدد الميزة التالية التي تريد العمل عليها أثناء انتظار المهمة الجارية

> من المحاضرة: «I'm pretty much completely locked out of doing any work from clawed code until now»

---

## 🟡 Phase 1: إنشاء worktree يدويًا

- [ ] 1.1 من داخل المشروع: `git worktree add -b feature/<اسم-الميزة> ../<مجلد-جديد> origin main`
- [ ] 1.2 اختر نقطة التفرّع: `origin main` أو اتركها فارغة للتفرّع من الفرع الحالي أو اختر فرعًا من GitHub
- [ ] 1.3 `cd ../<مجلد-جديد>` ثم `ls` للتأكد من وجود نسخة الكود
- [ ] 1.4 شغّل `claude` داخل المجلد الجديد وابدأ الميزة معزولة تمامًا

```bash
git worktree add -b feature/add-MFA ../add-MFA origin main
cd ../add-MFA
claude
```

> من المحاضرة: «I can start to implement my add MFA feature completely isolated from the current task»

---

## 🟠 Phase 2: الأتمتة عبر Warp agent mode

- [ ] 2.1 ارجع للمجلد الرئيسي وفعّل agent mode في Warp
- [ ] 2.2 اكتب: «create a new worktree branch to implement new UI fixes branch»
- [ ] 2.3 راقب Warp وهو يعمل fetch ثم `git worktree add` للفرع الجديد من `origin main`
- [ ] 2.4 اتبع إرشاده: `cd` إلى المجلد الجديد ثم شغّل `claude`

> من المحاضرة: «It's telling us we should cd into that folder now. Fire up claude and we're good to go»

---

## 🔵 Phase 3: التنظيف بعد الانتهاء

- [ ] 3.1 ادفع ([[push]]) كل عملك إلى GitHub أولًا
- [ ] 3.2 احذف الـ worktree: `git worktree remove <path>`
- [ ] 3.3 نظّف الفروع الراكدة دوريًا: `git worktree prune`

```bash
git worktree remove ../add-MFA
git worktree prune
```

> من المحاضرة: «This will just remove it once you've obviously pushed it up to GitHub»

---

## 🛠️ Troubleshooting (عند التعطّل)

| المشكلة | الحل من المحاضرة |
|---------|------------------|
| بطء/ثقل عند تكرار clone للمستودع | استخدم `git worktree` — يشارك الموارد ويبقي الفروع محدّثة مع الـ remote |
| فروع قديمة متراكمة | `git worktree prune` |
| لا أعرف صيغة الأمر | اطلبها من Warp في agent mode |

> 💡 **إضافة من المُلخِّص (ليست في المصدر):** لم يذكر المتحدث صراحةً أن `git worktree remove` يفشل إذا كانت هناك تغييرات غير مرحّلة — هذا سلوك عام في Git يُستحسن التحقق منه قبل الحذف.
