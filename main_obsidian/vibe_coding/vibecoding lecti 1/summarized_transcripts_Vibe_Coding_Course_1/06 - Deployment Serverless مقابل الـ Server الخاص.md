# 06 - Deployment: Serverless مقابل الـ Server الخاص

## الخلاصة العلمية المنظمة

طريقان للDeployment بعد اختيار Rendering:

### 1. [[Serverless]] (Serverless hosting)

لا تعرف بيانات Server. ترفع Code على GitHub وGitHub يحوّل automatic إلى SSG أو SSR.

**لماذا Serverless؟** قمة Security: صاحب الحاجة نفسه بلا بيانات Server؛ من يحاول «Hacking» لا يجد بيانات لأن الأشياء ليست على Server تقليدي.

#### أ) Static (SSG) مجاني أو شبه مجاني

| المنصة | ما ذكره المصدر |
|---|---|
| Cloudflare Pages | أهمهم؛ حتى 500 زائر يوميًا مجاني؛ بعدها 5 دولار/شهر. قمة Security لموقع Static بلا Server |
| Google Firebase | Static |
| GitHub Pages | Static |
| Surge.sh | جديد «عامل شغل جامد» للمواقع الStatic؛ رفع مجاني |

موقع الشركة الثابت: المبرمج يغيّر عبر GitHub فقط.

#### ب) Dynamic ssr(بيانات من AI / بحث / API خارجي / Database)

عائلة أصلها **AWS App Runner** (أمازون؛ «الأب الروحي» وغير مشهور). البدائل المشهورة:

| المنصة | حكم المصدر |
|---|---|
| [[Railway]] | الوسط؛ الأفضل من وجهة نظره. رابط تحت الفيديو: 20 دولار إن اشتركت من الـ Link، وإلا 5 |
| Vercel | يحاول البعد عنها؛ «الفترة الأخيرة بدأت تدعم الكيان» |
| Netlify وRender | مكلفان شوية |
| Fly.io | قوي جدًا للشركات الكبيرة التي لا مشكلة لديها في المال |
| Heroku | ذُكر ضمن القائمة |

### 2. الـ Server الخاص (Self-hosting) — Maximum control

تختار Server وتعمل Deployment بنفسك: Full Control على كل شيء، ومشكلة Security عليك. في الـ Serverless لا control إلا ربط GitHub بالحساب؛ لا بيانات Server. على منصات الـ Serverless مواصفات ملفات معيّنة للـ Rendering.

**Docker أساسي** لا نقاش؛ واجهته **[[Portainer]]** (لوحة تحكم لا Terminal؛ Vibe Coding لا يتعامل مع Terminal). Kubernetes ذُكر مع Docker.

### كيف تُستخدم هذه المفاهيم مع الذكاء الاصطناعي

أمثلة Prompt ذكرها: «Deployment على Cloudflare Pages؛ ساعدني في الإعدادات» — «Dynamic على Railway» (يطلب نوع ملفات داخل الـ Code) — Vercel يطلب Extension معيّنًا في الـ Backend — Portainer على الـ Server سيُشرح بعد قليل.

> [!info] الفترة المرجعية
> الأسطر 68–80.

### الاستخلاص العلمي

| وجه المقارنة | Serverless | Server خاص |
|---|---|---|
| بيانات Server | لا تعرفها | كاملة عندك |
| Security | قمة (لا بيانات تُسرَق من Server) | مسؤوليتك |
| التحكم | GitHub → المنصة فقط | Maximum control |
| أمثلة Static | Cloudflare Pages, Surge.sh | — |
| أمثلة Dynamic | Railway (المفضّل عنده) | Docker + Portainer على Hetzner/Vultr |
