# خطة العمل التطبيقية - الدرس الأول

> [!info] الغرض
> تحويل ما ورد في المحاضرة إلى **خطوات مرتّبة تنفّذية**، تخرج من القراءة إلى التطبيق. كل خطوة فيها ما تفعله بالضبط، والأداة المستخدمة، والمصدر من المحاضرة.

> [!tip] كيف تستخدم هذا الملف

> - مربع `[ ]` يعني لم تُنجز بعد. فعّله عند الإنجاز.
> - إن واجهت خطأً، انسخه Copy-بيست للذكاء الاصطناعي كما في خطوة **اكتشاف الـ Bug** في المرحلة 0.

## المرحلة 0 — التجهيزات (يوم واحد)

> من المحاضرة: «من يفكر بزنس يستثمر في المدفوع اليوم كي يبدأ يجلب مالًا لاحقًا.»

- [ ] اشترك في **Claude** (20$ أو 100$ أو 200$) — اختر خطة شهرية.
- [ ] اشترك في **ChatGPT** (20$ على الأقل) أو **Gemini** كنسخة احتياطية.
- [ ] **لا تستخدم النسخة المجانية** ولا DeepSeek للعمل.
- [ ] انضم لـ **Group School** (الرابط تحت الفيديو) — ضروري للدعم والأسئلة المعمّقة.
- [ ] أنشئ حساب **GitHub** إن لم يكن لديك.
- [ ] جهّز فكرة واضحة: أداة، كروم إكستنشن، أو موقع. اكتبها في جملتين.
- [ ] أثبت عقلية الـ Business: أنت لا تكتب Code، أنت تختبر أفكار.

## المرحلة 1 — تعلّم المفاهيم الأساسية (يوم–يومين)

> من المحاضرة: «عدم معرفة هيدلس يبني فرونت وباك في واحد ويمشي سكة غلط.»

### 1.1 المصطلحات الإلزامية (احفظها قبل أي شيء)

- [ ] **Frontend** (واجهة ما يراه المستخدم) — يكتب هنا: JavaScript.
- [ ] **Backend** (API + Database + Search) — يكتب هنا: Python.
- [ ] **Headless** = فصل الـ Frontend عن الـ Backend عبر API أو GraphQL.
- [ ] **Routing** = السيرفر يحوّل الطلب إلى الصفحة المناسبة.
- [ ] **Authentication** = هل الطلب له صلاحية الدخول.
- [ ] **Rendering** = تحويل البيانات إلى صفحة تُعرض (4 أنواع).
- [ ] **Deployment** = نشر الـ Code على الإنترنت.
- [ ] **Serverless** = استضافة بلا بيانات Server عندك (GitHub يكفي).
- [ ] **Self-hosting** = سيرفر خاص بك تتحكم فيه كاملًا.
- [ ] **Caching** = تخزين مؤقت لتسريع الطلبات المكررة.

### 1.2 استراتيجيات الـ Rendering

- [ ] **CSR**: JS في المتصفح، Server أخف. **لا يصلح لـ SEO.** استخدمه لتطبيقات تفاعل كثيرة.
- [ ] **SSR**: HTML يُعالَج في السيرفر لكل طلب. **أفضل SEO** لكن يحتاج سيرفر قوي. استخدمه لـ E-commerce وMarketplace.
- [ ] **SSG**: HTML محفوظ مسبقًا. **مثالي للـ Landing Page** والصفحات الثابتة.
- [ ] **ISR**: وسط بين SSG وSSR. استخدمه لمنتج بمراجعات أو stock غير محدود.

### 1.3 اختيار الـ Framework على أساس Rendering

- [ ] **Next.js** (الأشمل) → يدعم SSR + SSG + ISR، مناسب لكل شيء.
- [ ] **Astro** → SEO ممتاز، أصله static.
- [ ] **Vue** → تفاعل كثير (Cards/Forms)، كله Server-side.
- [ ] **React** فقط → تطبيقات Desktop/Workflow حيث الـ Client يتصرف.
- [ ] صفحة **Checkout** يجب أن تكون **SSR** (لا CSR ولا SSG).

## المرحلة 2 — تثبيت بيئة التطوير على جهازك (ساعتان)

> من المحاضرة: «VS Code وGitHub أساسيات لأي مبرمج؛ يكفي الربط بينهما.»

- [ ] ثبّت **VS Code** أولًا (لا Cursor مباشرة).
- [ ] ثبّت **Node.js** من google.com.
- [ ] ثبّت **Python** (الإصدار 3.11 أو 3.12 — لا 3.13 بعد).
- [ ] ثبّت **Git for Windows**.
- [ ] افتح VS Code → Extensions → ابحث عن **GitHub Pull Requests** → Install.
- [ ] Extensions → ابحث عن **Claude Code** (الأهم) و**Codex** → Install.
- [ ] اربط VS Code بـ GitHub: افتح الـ Extension → Sign in → Authorize.
- [ ] اختبر: افتح Terminal واكتب `npm -v` و`python --version`، يجب أن تظهر الأرقام.

> [!note] ملاحظة
> لاحقًا إن أردت AI Editor كامل: ثبّت **Cursor** (مبني على VS Code)، وستجد Extensionsك عليه.

## المرحلة 3 — اختر طريقة الاستضافة (قرار مهم)

> من المحاضرة: «أدوات Dynamic → Railway. موقع Static → Cloudflare Pages. Self-host → Server خاص.»

### 3.1 قرّر حسب مشروعك

| نوع مشروعك | اختر | التكلفة |
|---|---|---|
| صفحة هبوط / مدونة / Documentation | **Cloudflare Pages** | مجاني حتى 500 زائر/يوم، بعدها 5$/شهر |
| أداة Dynamic / Dashboard / AI Agent | **Railway** | 20$ من لينك الفيديو، 5$ من التسجيل المباشر |
| VPS كامل لتطبيقاتك ومواقعك | **Hetzner** (أرخص) أو **Vultr** (أقوى) | 30$–40$/شهر |

- [ ] اتخذ قرارك وسجّله هنا: ________________

### 3.2 إن اخترت Serverless (الأسهل للبداية)

#### المسار A — Cloudflare Pages (Static)

- [ ] ادخل cloudflare.com → Pages → Connect to Git.
- [ ] اختر الـ Repo.
- [ ] Build command: `npm run build` (مثلاً).
- [ ] Build output: `out` أو `.next` أو حسب الـ Framework.
- [ ] Deploy.

#### المسار B — Railway (Dynamic) — **الموصى به للبداية**

- [ ] ادخل railway.app من اللينك تحت الفيديو (رصيد 20$).
- [ ] أنشئ مشروع **New Project** → **Deploy from GitHub repo**.
- [ ] Install GitHub App → Authorize.
- [ ] اختر الـ Repo → Deploy.
- [ ] بعد أن يصبح الـ Service أخضر: **Variables** → أدخل كل ما في `.env`.
- [ ] **Settings** → **Generate Domain** (أو Custom Domain).
- [ ] Port غالبًا **8080** (اقرأ `railway.toml`).

> [!important] نقطة حاسمة
> Railway تفرض ملف **`railway.toml`** داخل المشروع. اطلب من الذكاء الاصطناعي أولًا: «أنا عندي مشروع Next.js، اعمل Deployment على Railway واعمل لي الملفات اللازمة.»

### 3.3 إن اخترت Self-host (VPS خاص)

- [ ] اشترِ VPS من Hetzner أو Vultr.
  - Hetzner: من اللينك تحت الفيديو (رصيد 20$).
  - Vultr: من اللينك تحت الفيديو (رصيد 300$ أول شهر).
- [ ] اختر **Ubuntu 24** (أو 25 إن كانت stable حين تشتري).
- [ ] **Dedicated CPU** بسعة 2 CPU + 8GB RAM (أو 4 CPU + 16GB).
- [ ] إن كان الموقع عربي → اختر **Location** ألمانيا. غير ذلك → أمريكا (نيويورك).
- [ ] ادفع بـ PayPal (Hetzner) أو Credit Card. Hetzner يتطلب رفع جواز سفر للتحقق أول مرة.

## المرحلة 4 — إعداد السيرفر (ساعة–ساعتان)

> من المحاضرة: «Portainer مجاني 100%. Docker أساس لا نقاش.»

### 4.1 الاتصال بالسيرفر

- [ ] حمّل **PuTTY** من google.com.
- [ ] افتح PuTTY → حقل **Host Name**: IP السيرفر → Open.
- [ ] login as: `root`.
- [ ] الصق Password: **كليك يمين** (لا Ctrl+V) → Enter.
- [ ] إن طلب تغيير Password (Hetzner فقط): الصق القديم، ثم الجديد مرتين.
- [ ] اختبر: اكتب `ls` واضغط Enter — يجب أن تظهر ملفات.

### 4.2 تثبيت Docker + Portainer

- [ ] افتح Claude أو ChatGPT واسأل: **«أوامر تثبيت Portainer على Ubuntu 24»**.
- [ ] انسخ الأوامر إلى PuTTY واحدًا تلو الآخر (كليك يمين للصق، Enter بعد كل أمر).
- [ ] أي سؤال أثناء التثبيت: اكتب `Y` ثم Enter.
- [ ] بعد اكتمال التثبيت: افتح المتصفح وادخل على:
  ```
  https://IP-SERVER:9443
  ```
- [ ] إنشاء Admin User (ألغِ الـ checkbox التي تسأل عن بيانات إضافية) → Create.
- [ ] على Vultr فقط: افتح البورت 9443 (Hetzner مفتوح باي Default).
  ```bash
  ufw allow 9443
  ```

### 4.3 تثبيت Nginx Proxy Manager (لربط الدومين)

- [ ] اسأل الذكاء الاصطناعي: **«أوامر تثبيت Nginx Proxy Manager على Portainer»**.
- [ ] ادخل Portainer → Stacks → Add Stack.
- [ ] الصق الملف (Compose) من الذكاء الاصطناعي → Deploy.
- [ ] افتح: `http://IP-SERVER:81`.
- [ ] Default Login: `admin@example.com` / `changeme` → غيّرها فورًا.
- [ ] فعّل SSL لاحقًا بعد ربط الدومين (الخطوة 5.2).

## المرحلة 5 — ربط الدومين (Cloudflare)

> من المحاضرة: «Cloudflare Pages قمة Security.»

- [ ] اشترِ Domain (Namecheap / Cloudflare Registrar / Porkbun).
- [ ] ادخل Cloudflare → اختر الدومين → **DNS** → Add Record:
  - Type: **A**
  - Name: `@` (للدومين الرئيسي) أو اسم Subdomain (مثل `app`).
  - Content: **IP السيرفر**.
  - Proxy: **ON** (برتقالي) — هذا يعطيك CDN + حماية.
- [ ] SSL/TLS → Full (Strict).
- [ ] ارجع لـ **Nginx Proxy Manager** → Proxy Hosts → Add:
  - Domain Names: الدومين أو الـ Subdomain.
  - Forward Hostname/IP: `IP-SERVER` أو `localhost`.
  - Forward Port: البورت الخاص بالتطبيق (5678 لـ n8n مثلاً).
  - Scheme: http.
- [ ] Save.
- [ ] Edit على نفس الـ Host → SSL → **Request** Certificate → Force SSL.
- [ ] إن كان التطبيق يحتاج Data Instant (مثل n8n) → فعّل **WebSocket Support**.

## المرحلة 6 — ارفع مشروعك الأول

> من المحاضرة: «GitHub تفاصيل كثيرة جدًا. الذي لقّن هنا: ربط GitHub بـ VS Code — هذا وحده يمشي في Vibe Coding.»

### 6.1 محليًا (على جهازك)

- [ ] افتح VS Code → File → Open Folder → اختر مجلد فارغ.
- [ ] افتح Terminal واكتب (مثال Next.js):
  ```bash
  npx create-next-app@latest my-app
  ```
- [ ] اتبع اختيارات المصدر:
  - TypeScript: **Yes**
  - Tailwind: **Yes**
  - ESLint: **Yes**
  - App Router: **Yes**
  - Turbopack: **No**
- [ ] `cd my-app` ثم `npm run dev` → افتح `http://localhost:3000`.

### 6.2 على GitHub

- [ ] في VS Code → Source Control → **Publish to GitHub**.
- [ ] اختر Public أو Private.
- [ ] افتح GitHub → تأكد أن الـ Repo ظهر.

### 6.3 الـ Deployment (حسب اختيارك في المرحلة 3)

**إن اخترت Railway:**
- [ ] ادخل railway.app → New Project → Deploy from GitHub Repo.
- [ ] اختر `my-app`.
- [ ] انتظر حتى يصبح أخضر (≈ 5 دقائق).
- [ ] Settings → Generate Domain → افتحه.

**إن اخترت Cloudflare Pages:**
- [ ] Workers & Pages → Create → Pages → Connect to Git.
- [ ] اختر `my-app`.
- [ ] Framework preset: Next.js.
- [ ] Build command: `npm run build`.
- [ ] Output dir: `.next`.
- [ ] Save and Deploy.

**إن اخترت Self-host (Portainer):**
- [ ] في Portainer → Stacks → Add Stack.
- [ ] الصق ملف Docker Compose (اطلبه من الذكاء الاصطناعي).
- [ ] Add environment variables.
- [ ] Deploy.
- [ ] تأكد أن الـ Container يعمل من Containers.

## المرحلة 7 — ضبط الـ Backend (للمشاريع المتقدمة)

> من المحاضرة: «Python أهم لغة تتعاون مع الذكاء الاصطناعي.»

- [ ] Backend API: **Python** مع **FastAPI** + **DSPy**.
- [ ] DSPy: تثبّتها في الباك إند لتحسين الـ Prompt تلقائيًا.
- [ ] **Database**: PostgreSQL (مفتوح المصدر).
- [ ] الذاكرة + Vector Search: **Redis** (أصبح يفعل الاثنين معًا).
- [ ] Search: **Typesense** (مفتوح ومجاني).
- [ ] Analytics (لو كبر المشروع): **ClickHouse** بدل Postgres.

### خيارات استضافة Database

- [ ] **Serverless** (الأسهل): Neon.com / Supabase / Railway (≈ 5$/شهر).
- [ ] **Self-hosted**: Postgres على نفس سيرفر Portainer.

## المرحلة 8 — دورة العمل بعد الإطلاق (مستمرة)

> من المحاضرة: «بعد Sonnet 4.5 وChatGPT 5: مجرد Copy-بيست بلا اعمل لي ولا Prompt.»

### 8.1 حل المشاكل (مهم جدًا)

- [ ] عند ظهور Bug في المتصفح: افتح DevTools (F12) → Console.
- [ ] انسخ رسالة الخطأ **Copy-بيست كاملة**.
- [ ] الصقها في Claude/ChatGPT.
- [ ] لا تكتب «اعمل لي» ولا Prompt طويل. **فقط الـ Bug نفسه.**
- [ ] الذكاء الاصطناعي يحل المشكلة ويعطيك التعديل.
- [ ] طبّق التعديل → اختبر محليًا → `git push` → الـ Deployment Automatic.

### 8.2 تطوير مستمر

- [ ] كل تغيير: VS Code → عدّل → Source Control → Commit → Push.
- [ ] Railway يلتقط التغيير تلقائيًا ويعيد الـ Deploy.
- [ ] في Railway: Activity → **Rollback** متاح لأي نسخة سابقة.
- [ ] أضف إكستنشينات جديدة تدريجيًا حسب الحاجة (اطلب من الذكاء الاصطناعي).
