# 07 - Backend: API وقاعدة البيانات والبحث

## الخلاصة العلمية المنظمة

الـ Backend غالبًا: [[API]] + قاعدة بيانات + بحث. عند المبرمجين «كله API».

### البحث

ال <span style="color:#0D9488; font-weight:bold;">Typesense</span>: القمة في البحث، مصدر مفتوح ومجاني؛ يُثبَّت على Portainer. بحث سريع قوي مناسب للذكاء الاصطناعي.

### الـ API

الـ Backend API خاص بالذكاء الاصطناعي عبر **Python** — أهم لغة تتعاون مع الذكاء الاصطناعي. مستقبلًا إن عملت موديلًا خاصًا بك بدل ChatGPT/Claude فلن يكون إلا بـ Python.

لضبط Prompt داخل Backend كل فترة: مكتبة <span style="color:#0D9488; font-weight:bold;">DSPy</span> على Python. تحسّن Prompt؛ تُثبَّت في Backend وتعطيك Prompt المضبوط لكل Request. مفتوحة المصدر ومجانية 100%. أهم مكتبتين: **FastAPI** مع **DSPy**.

### قاعدة البيانات

أعلى قيمة: <span style="color:#0D9488; font-weight:bold;">PostgreSQL</span> — مفتوحة المصدر ومجانية. أخطر عنصر Security في أي Web Application هو Database (ثم الـ API).

| مسار Deployment | المنصات / التكلفة كما وردت | ملاحظة المصدر |
|---|---|---|
| Serverless (أقصى Security) | Neon.com، [[Supabase]] (أشهرهم)، Railway، PlanetScale | Neon وRailway وSupabase تبدأ مجاني ثم مدفوع؛ المجاني لا يستمر كثيرًا. PlanetScale بلا مجاني؛ تربو سبيد؛ أقل سعر 60 دولار؛ للشركات الجاهزة |
| على الـ Host الخاص | Postgres على الـ Server مع الانتباه للـ Security | يناسب الميزانية؛ Frontend وكل شيء عندك |

تكلفة تقريبية ذكرها: من Neon/Railway تمشي بـ 5 دولار/شهر؛ Supabase أقل شيء 20 دولار «في حالة الماكس» لأقصى Security.

خطوتان على Supabase أو Neon (Railway خطوة أو خطوتين) فتصير Database جاهزة.

### إن كان الشغل ذكاءً اصطناعيًا: الذاكرة

الذكاء لا يبقى فاكر الشات وID الشات إلا بحفظ على **[[Vector Database]]**. أنواع كثيرة؛ الذي أثبت قدرته ويناسب كل الأوقات: **[[Redis]]** — Memory وVector DB في وقت واحد بعد التحديثات الجديدة.

### Analytics

إن كبرت بيانات التحليل (مثل SEO) على Database الأساسية تثقل الموقع. الحل: **ClickHouse** — يعمل Postgres أيضًا لكن مضبوط على Analytics فقط؛ مصدر مفتوح ومجاني؛ يُثبَّت على الـ Server ويوفّر load الـ Server.

> [!tip] لماذا طالت المقدمة؟
> قضى نحو نصف ساعة في المقدمة لأنها — بلاها — لا تعرف كتابة Prompt تقول فيه ماذا تريد. فهم Static وSSR وأنواع Framework والـ Serverless والـ Self-hosting كمفاهيم (لم تُرَ عمليًا بعد) يغيّر اتجاه البناء. مثال: عدم معرفة [[Headless]] يبني Frontend و Backend في واحد ويمشي سكة غلط.

> [!info] الفترة المرجعية
> الأسطر 81–94.

### الاستخلاص العلمي

| المكوّن | الاختيار الذي سمّاه المصدر |
|---|---|
| بحث | Typesense |
| API | Python + FastAPI + DSPy |
| DB أساسية | PostgreSQL |
| ذاكرة/Vector | Redis |
| Analytics | ClickHouse |
