# 04 - كيف تعمل صفحة الويب: Routing وAuthentication وجلب البيانات

## الخلاصة العلمية المنظمة

- سيُعمل **Web Application** لا مدونة ولا أشياء WordPress.
- أي موقع إنترنت يتكوّن من: **HTML + CSS + JavaScript**. JavaScript أهم كور؛ CSS وHTML سهلة حتى لمن لم يدرس برمجة. JavaScript فيها خلافات ومشاكل كثيرة.

### لماذا ظهرت المكتبات (من 2011)

ملفات JavaScript كثيرة وتعمل لودًا كبيرًا. سنة 2011 بدأ نظام المكتبات:

| السنة | المكتبة | ملاحظة المصدر |
|---:|---|---|
| 2011 | Angular | أول مكتبة؛ تحمل JS/مكتبات جاهزة لتوفير وقت البرمجة. |
| 2013 | React | رعاها Facebook؛ خرج منها Next.js وRemix. |
| 2014 | Vue | مكتبة شبيهة بريأكت تختلف في بعض الأساليب. |
| 2016 | Svelte | من أواخر الFrameworks. |

بجانب كل مكتبة يُكتب SSR وSSG؛ يشرحها بعد قليل.

### ماذا يحدث عند طلب الصفحة

1. المستخدم يضغط رابطًا. المتصفح (Mobile أو Desktop) يرسل **request** للServer.
2. Server يعمل **[[Routing]]**: يحوّل إلى الصفحة/الملفات المطلوبة.
3. يفحص **[[Authentication]]**: هل الطالب authenticated وله access أم لا.
4. يجلب البيانات من API أو قاعدة البيانات (Backend).
5. يحدث **[[Rendering]]** — أربع طرق تُختار عليها Framework (الجزء التالي).

> [!tip] لماذا هذه الألفاظ؟
> من يعمل Vibe Coding بلا هذه المفاهيم لا يعرف ماذا يقول للذكاء الاصطناعي. لا تقل «اعمل لي صفحة write page»؛ قل **Routing**. كذلك الـ Authentication وRendering ألفاظ تُكتب في Prompt.

> [!warning] تنبيه
> أدوات مثل Lovable — بحسب المصدر — لا تعرف عمل Authentication؛ آخرها تربطك بـ Supabase وتجعل الAuthentication من خلالها. هنا لا مشكلة في العمل مع Supabase أو غيرها.

> [!info] الفترة المرجعية
> الأسطر 33–42. وردت أثناء الشرح عبارة «صل على محمد وعليه الصلاة والسلام» داخل تعداد مكونات الصفحة.

### الاستخلاص العلمي

| المفهوم | دوره عند طلب الصفحة |
|---|---|
| [[Routing]] | تحديد أي صفحة/ملف يُظهر. |
| [[Authentication]] | هل للطلب صلاحية الدخول. |
| جلب البيانات | من API أو Database أو Search. |
| [[Rendering]] | تحويل البيانات إلى صفحة تُعرض. |
